# 数方 Suguru · 区域推理（零猜测区域填数）

> *题面只给你区域怎么分块。每个装 k 格的区域里必须恰好是 1..k 各一个，挨着的格子（连对角算）不能同数——
> 每一局在出货前都被那四条铅笔规则从空盘推到底过一次，唯一解由第二套互不信任的穷举计数器逐格复核。*

浏览器原生的**单人区域推理盘**（Suguru / Statix）：无构建步骤、无打包器、**零美术与音频文件**——
区域底色、粗边界、数字、绿环全部 canvas 现画，音效由 WebAudio 合成。

玩法：盘被粗边界切成若干不规则区域。把数字填进格子，使得**每个 k 格区域恰好装下 1..k 各一次**，
并且**任意两格——上下左右和四个斜角——数字不同**。区域越大，能填的数越多，也越受邻居挤压。
没有运气题：每一局都只有一个答案，且每一局都能靠逻辑推到底。

- **核心承诺 1｜零猜测**：出货的每一局都能 **只用那四条规则从空盘推到底**。这不是文案，是准入门槛——
  挖洞阶段每抹掉一个提示数都重跑一遍铅笔路径（`js/engine/generate.js` 的 `craft()`），推不动就把这一格填回去。
- **核心承诺 2｜唯一解**：`countSolutions()`（`js/engine/count.js`）是一台**不含任何推理规则**的逐格穷举计数器，
  自己从 `(w, h, groups, givens)` 重建邻接与区域表。它和铅笔路径从两个方向回答同一个问题；
  烧过 400k 节点的候选盘判 `OVERBUDGET` **直接淘汰，不出货**——所以"这一局唯一解"在交付的每一局上都是**证完的**，
  不是"没证完先算过"。
- **核心承诺 3｜提示不是答案**：提示走的是**同一条**铅笔路径（`buildScript()` 在出货时就把推导脚本记下来了），
  所以它必须点名用了哪条规则、落在哪一格（`第3行第2列 只能填 3：1（4 号区域（7 格） 里 第1行第1列 已是 1）、4（第4行第3列 贴着它且已是 4）…。所以那一格是 3。`）；
  玩家已经和题面矛盾时，提示**拒绝落子也不计入求助次数**，只把矛盾说给你听。
- **核心承诺 4｜推理机不会乱写**：`tools/engine-test.mjs` 的头一条不是"能推完"，而是
  **每一步推论都必须和出题那盘答案逐格对得上**——把生成器的正解当裁判，任何一条规则写错一格就红。
  这一条抓的是"推错了"，比"推不动"值钱。
- **核心承诺 5｜同一个种子在任何引擎上画同一张盘**：抽盘条件里不许掺墙钟，随机数也不许交给 `sort` 的比较器
  （比较次数是实现相关的）。这一条是被真实事故逼出来的：修好之前同一个 seed 在 node 抽出 26 个提示的盘、
  在 Chrome 抽出 22 个——"存档只记 seed"当场失效。现在 `tools/golden.mjs` 存着五张实测盘的指纹，
  **node 门禁和浏览器门禁各自量一遍**，谁漂了谁红。
- 难度不是标签：`初学 → 大师` 五档的分数带是**实测**出来的（`npm run balance` 打印分位表 + 漂移门禁），
  最大档只到 9×9，**为什么不能更大是量出来的**，写在 `js/engine/generate.js` 的恒等式注释里。
- 规模：**10 个 ES Module / 2,273 行 JS** + 7 个验证脚本 1,644 行 + 574 行 CSS/HTML，**运行时依赖 0 个**
  （Electron 只是 devDependency，桌面壳和网页跑的是同一份代码）。
- 验证：**引擎不变量全绿**（四条规则的 soundness 探针 / 独立计数对账 / 逐格改一数的答复 / 五档出货 / 跨引擎指纹）
  + **310 项浏览器断言**（9 个场景，读 DOM 几何与画布像素，不读标志位）。
- **在线试玩**：<https://z-biz-game.github.io/z-biz-game-suguru-cos/>（`main` 分支推送即自动部署）

```bash
npm start            # 零依赖静态服务 → http://127.0.0.1:5272
npm run dev          # 同一个端口，显式写法（verify.sh 用的就是 5272）
npm run electron     # 桌面壳（electron/main.cjs，同一份代码）
```

```bash
npm run check        # 逐文件 node --check 语法门禁
npm test             # 引擎不变量：规则 soundness / 独立计数对账 / verify 收拒 / 跨引擎指纹
```

## 玩法

| 操作 | 行为 |
|---|---|
| **点一格** | 选中它（琥珀框）。题面给的格是冷白数字，选中的时候框是蓝的——那是"不能改"的意思 |
| **点数字键 1..9** | 写进选中的格；**再点同一个数就是擦掉**（省掉一次寻路成本） |
| **擦掉**（或 `0` / `Backspace` / `Delete`） | 把这一格收回空 |
| **方向键** | 在盘上走格，键盘玩家和指针玩家用的是同一个 `sel` |
| **提示**（或 `H`） | 给出题面已经强制、而你还没写下的下一格，点名规则；真的落子，也真的计入求助次数 |
| **撤销**（或 `Z`） | 退掉一步。**步数退，求助次数不退**——退掉一次提示只退脚本游标，好让那一步还能被说一遍 |
| **换一局**（或 `N`） | 换一张新盘。种子是在**界面这一层**抽的（`js/main.js` 的 `freshSeed`），生成器仍然只吃 seed——抽出来的 seed 会跟着续局存档写回去，所以"只记 seed 就能重画同一张盘"对新盘照样成立（`play` 场景钉着这一条） |
| **Esc** | 回选档；这一局自动留下续局 |

判胜用的是 `verify()`：只读盘面，按规则原文核对"每个区域是不是 1..k 各一次、八邻有没有同数"。
它不读推导脚本也不读 UI 记账，所以**提示逻辑写错也伪造不出一场胜利**。
填错的格不会被系统擦掉，但会被**描一圈红 + 读数条标红 + 状态行说人话**
（`第2行第3列 与 第2行第4列 相邻却同为 4`），红色只是附加层，形状（圈）才是主载体。

## 四条规则（提示只会说这些）

| 规则 | 说什么 | 权重 |
|---|---|---|
| 只此一格 `only` | 这一格只剩下一个数填得进去 | 1.2 |
| 缺数只剩这格 `last` | 区域里这个数只有这一格放得下 | 1.8 |
| 邻格挤压 `squeeze` | 这个数在区域里只能落在贴着某格的几格里，那格就不能是它 | 3.4 |
| 反证 `nishio` | 假设这格填它，剩下的数就放不下了 | 6.0 |

前三条都是**必要条件**：真解既然存在就必须满足它，所以规则落下的每一格在该盘面的**每一个解**里都成立。
`nishio` 是唯一一条"试一步"的规则，它被严格限制成**只做一层假设、且只在必要条件上判真假**，
所以它同样不会把猜测写成事实（见 DESIGN §5、§6）。

规则不是越多越好。这里曾经还有第五条——**二联锁定**（区域里两格候选恰好是同一对数，别处不能再有它们）。
实测 300 张出货盘（5 档 × 60 种子）里它出场 **0 次**，另外 15k+ 个中途局面里也是 **0 次**：
这层的减法只在"把某一格削到只剩一个数"时才落子，而二联锁定天生是划线不是落子。
留着一条永远不出场的规则，等于在难度分和提示词表里虚报一项，所以删掉了。

## 难度是量出来的

`SAMPLES=24 npm run balance`（每档 24 个种子，2026-09-28，空载机器；CI 跑的就是这一档配置）：

| 档 | 盘面 | 区域数≈ | 区域上限 | 分数带（选取目标） | 实测中位 | 命中 | 平均抽几次（最坏） | 提示 少/中/多 | 出题 p95 | 最慢 |
|---|---|---|---|---|---|---|---|---|---|---|
| 初学 trainee | 5×5 | 5 | 7 格 | 15–27 | 21.4 | 24/24 | 1.3（2/40） | 6–10–14 / 25 | 10.9 ms | 14.7 ms |
| 上手 apprentice | 6×6 | 7 | 8 格 | 22–40 | 25.2 | 24/24 | 1.2（3/40） | 9–14–19 / 36 | 19.3 ms | 24.9 ms |
| 熟练 regular | 7×7 | 9 | 8 格 | 30–49 | 34.8 | 24/24 | 1.3（2/40） | 15–18–25 / 49 | 45.1 ms | 53 ms |
| 高阶 expert | 8×8 | 12 | 8 格 | 44–63 | 59.6 | 24/24 | 1.7（5/40） | 19–26–30 / 64 | 180.1 ms | 186.8 ms |
| 大师 master | 9×9 | 14 | 8 格 | 56–73 | 63.4 | 24/24 | 1.2（2/40） | 30–34–39 / 81 | 101.4 ms | 104.6 ms |

档位排的是「盘面多大」×「区域多密」×「留下多少提示」，五档中位数严格单调
（`21.4 < 34.8 < 36.4 < 59.6 < 63.4`，不单调就红）。分数是**推理步数的加权和**（每步按上表权重计），
所以它同时反映盘有多大、线索有多稀、要用到多贵的规则。
每档"实测建议带"（15~85 分位）都落在档位表写的带里，`balance` 会盯住这个偏差不许越界。

出题耗时那一列要老实说：分布是**双峰**的——一次抽中的盘几毫秒，烧到抽取上限的盘要慢一个数量级，
所以中位数代表不了"点新的一局要等多久"。`budgetMs` 记的是**每档实测 p95 基线**，
门禁是"这一档的 p95 别比基线慢一倍"（`p95 > budgetMs × 2` 就红），绝对值每次照常打印。
高阶那一档 p95 180 ms、最慢 187 ms，界面上有遮罩挡着，不让玩家对着不动的画布猜。

## 上线的到底是哪一批文件

这个仓没有打包器：站点=一次文件拷贝。以前「拷哪些」写在 `pages.yml` 的 `run:` 里（手抄的几行
`cp`）。本地 `index.html` 直读仓库根，永远自洽；线上却按那份清单拷，于是页面后来引用的
`manifest.webmanifest`、`sw.js`、`icons/*` 可能一个都没上去——线上 404，而仓里的引擎测试与
真浏览器闸全绿，因为它们跑的都是仓库根，没有任何一步在「按清单拷」的那个环境下加载过页面。

现在清单只有一份，住在 `tools/assemble-site.sh`：CI 调它拷 `_site`，本地闸调它拷临时目录，
然后**对拷出来的产物**提要求（`tools/deploy-set.mjs`）：

- **W 清单与页面同源**：`pages.yml` 里必须真有 `run: bash tools/assemble-site.sh <dir>` 这一行，
  `ci.yml` 里必须真有 `run: node tools/deploy-set.mjs`。认的是调用那一行，不是文件里出现过这个
  路径——注释里本来就会写它，只 grep 字符串会被一句散文喂绿。
- **R 引用可达**：引用不靠手打名单。从 `index.html` 的 `href/src` 出发，凡解析出来是 `.js`/`.css`
  的就把那一站也扫一遍（CSS 的 `url()`、JS 去掉注释后的 `'./…'` 字面量、`new URL(x, base)` 的两种
  基、`navigator.serviceWorker.register`、`scope`），`manifest` 的 icons/screenshots/shortcuts 各自
  的 `src` 也算引用。取径上读不到的那一站本身就是红（读不到＝这一站根本没扫）。每条引用都必须在
  产物里且非 0 字节；绝对路径单列一条红，因为 Pages 挂在 `/<repo>/` 前缀下会跳出去。
- **P 位图不许说谎**：`manifest` 声明的 `sizes` 必须等于 PNG IHDR 的真实宽高。
- **钉住两个数**：`EXPECT_CHECKS=26`（R 段实际检查的路径条数）与 `EXPECT_ROWS=44`
  （这一次跑的断言条数）。没改页面却掉了，说明解析断了；删掉一张图标会同时少一条 R10 与那张的
  P1/P2，所以两个数一起钉，rows 能漂就是闸在缩水的信号。

`tools/deploy-set-selftest.mjs` 是这两颗钉的阳性证明：它把仓库复制到临时目录，照着每一类断言
各下一刀（X1 清单不收位图目录 / X2 模块边改名 / X3 CSS 写绝对路径 / X4 `start_url` 绝对 /
X5 删光 >=512 图标 / X6 少一个必填字段 / X7 声明尺寸与真图不符 / X8 workflow 不调脚本 /
X9 CI 不跑闸 / X10 是阴性对照——往入口 JS 追加一行只写在注释里的假路径，闸必须仍然绿、条数仍然
`26`、rows 仍然 `44`；X11 og:image 退回相对路径 / X12 og:image 的前缀指向别的 slug），
要求每一刀都让闸**点名**变红。靶子从 `DEPLOY_SET_DUMP=1`
的出处表现挑，所以页面改了、仓与仓不同，台架跟着走。

`node tools/deploy-set.mjs` 与 `node tools/deploy-set-selftest.mjs` 就是 CI 跑的那两条命令本身
（package.json 里的 `deploy-set` / `deploy-set:selftest` 只是同一支脚本的 npm 入口）；把它们接进本仓
那条浏览器 one-shot（`tools/verify.sh`）还欠着——那道脚本的腿名单与条数钉是每个仓自己的形状。
